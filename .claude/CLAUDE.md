# MCP Platform

Nền tảng chạy và quản trị nhiều AI Agent. Mọi hành động lên hệ thống thật đi qua MCP Tool có kiểm soát quyền, audit và tính chi phí. Go modular monolith: một repo, ba process (`api`, `gateway`, `worker`).

## Trạng thái hiện tại

**Phase 1: phạm vi đã hiện thực; Phase 2: xong bốn lát "Temporal + worker", "Model Router", "Budget", "Approval + tool ghi", lát "Orchestrator" (`mode: planned`, delegation, pause / resume, đề xuất kế hoạch bằng LLM), nén context deterministic và luồng sự kiện SSE: mọi gạch đầu dòng của phạm vi Phase 2 đã có hiện thực** (chạy đầu-cuối trên máy cục bộ; chưa triển khai staging, chưa có Cloud KMS). ADR 0001–0010 đã Chấp thuận; ADR-0011 (Keycloak làm IdP), ADR-0012 (provider khoá cục bộ trước Cloud KMS) và ADR-0017 (triển khai một máy chủ bằng Docker Compose, Temporal tự vận hành) cũng đã Chấp thuận; ADR-0013 (Claude CLI cho local, Anthropic API cho production), ADR-0014 (tool nội bộ của runtime; điểm quyết định delegation trong database) và ADR-0015 (workflow của người dùng biên dịch thành execution `planned`; lịch chạy tạo lần chạy ở `api`) còn Đề xuất. **Phase 3:** lát "workflow + lịch chạy" đã có hiện thực trên máy cục bộ (xem mục Workflow bên dưới); các lát còn lại chưa làm. Use case dẫn đường: DevOps Agent chỉ đọc trên Docker.

Đã có:

- Binary: `cmd/api`, `cmd/gateway`, `cmd/worker` (Temporal worker chạy vòng lặp Agent; wiring ở `internal/workerserver`), `cmd/integration-docker` (managed MCP server), và công cụ `cmd/migrate`, `cmd/hqadmin` (tạo organization + quản trị viên đầu tiên; đăng ký / discovery / duyệt MCP server và phân loại tool; đều qua role `app_admin`).
- Xác thực OIDC (`internal/platform/identity`): kiểm tra JWT, tạo user ở lần đăng nhập đầu, chọn tenant từ membership (claim `org_id` chỉ là gợi ý). JWKS cache trong bộ nhớ: khi cache còn rỗng (process vừa khởi động) request tới trong lúc đang tải khoá chờ lần tải đó thay vì bị từ chối 401.
- RBAC (`internal/platform/authz`): `Decide` / `Require`, role dựng sẵn seed trong migration, danh mục permission là hằng số trong code.
- Endpoint `/v1/organization`, `/v1/projects` (`internal/platform/tenancy`): ETag / If-Match, phân trang keyset, lỗi RFC 9457.
- `internal/apiserver` là composition root của API; `internal/adminops` là đường code xuyên tenant, không process nào import.

- Audit trail (`internal/audit`): `audit.Record(ctx, tx, Event)` trong cùng transaction với thay đổi, ở cuối transaction. Việc ghi đi qua hàm `audit_append` trong database (tự lấy giờ, tính hash, tuần tự hoá theo org); role ứng dụng không ghi trực tiếp được. Từ chối quyền được ghi kèm quy tắc, lặp lại thì gộp.
- `Idempotency-Key` (`internal/platform/idempotency`): `idem(authorize, handler)`; quyền được kiểm trước khi nhận key hay phát lại. Chỉ bọc thao tác tự khử trùng; không bọc endpoint trả secret (xem ghi chú đầu package).
- Kiểu request / response sinh từ `openapi.yaml` bằng `oapi-codegen` vào `internal/api` (chỉ model; handler vẫn là `net/http`).
- Realm Keycloak cho dev được import tự động (`deployments/compose/keycloak/hq-realm.json`).
- Agent Catalog (`internal/agent/catalog`): Agent + Agent Version bất biến (trigger ở DB), lifecycle `draft → active ⇄ disabled → archived`, publish / rollback qua `active-version`. Version tham chiếu tool, ghim model (`policy: fixed`), delegation hoặc isolated runtime **bị từ chối** cho tới khi có Tool Registry / Model Catalog / Orchestrator: validator được tiêm qua interface `ToolValidator`, `ModelValidator`.
- LLM provider (`internal/ai/provider`): hợp đồng `Provider.Complete` = đúng một lượt của model, không tự chạy tool. Adapter `claudecli` gọi Claude Code CLI như một model, **chỉ khi `HQ_ENV=local` và `HQ_ENABLE_CLAUDE_CLI=1`** (ADR-0013). Adapter `anthropic` (`internal/ai/provider/anthropic`, SDK Go chính thức, tool use gốc, streaming) chạy trong process `gateway`; nó đổi tên tool `<server>.<tool>` thành `<server>__<tool>` trên dây và giữ nguyên khối suy luận giữa các lượt qua `Opaque`. Chạy thử với API thật: `HQ_TEST_ANTHROPIC=1 HQ_ANTHROPIC_API_KEY=… HQ_TEST_ANTHROPIC_MODEL=<model id> go test ./internal/ai/provider/anthropic -run Real -v` (tốn tiền thật). Chạy thử với CLI thật: `HQ_TEST_CLAUDE_CLI=1 go test ./internal/ai/provider/claudecli -run Real -v` (tốn hạn mức tài khoản).
- Model Catalog (`internal/ai/modelcatalog`) và bảng giá (`internal/cost/pricing`): provider / model phạm vi platform (tenant chỉ đọc) hoặc org; giá bất biến, không lùi về quá khứ; tenant chỉ đặt giá cho model của chính org. `api_key` và `base_url` của provider bị từ chối cho tới khi có Secrets và SSRF guard. Agent Version ghim được model (`policy: fixed`), kiểm lại khi publish.
- MCP server Docker chỉ đọc (`internal/integration/docker`): `list_containers`, `inspect_container`, `get_container_logs`; không trả env, label, command. Chỉ nhận request mang ngữ cảnh do Gateway ký (`internal/shared/signedctx`, Ed25519: server chỉ giữ khoá công khai `HQ_SERVICE_VERIFY_KEY`, ADR-0018); `get_container_logs` chỉ chạy trong execution. Một Docker host thuộc đúng một org (`HQ_DOCKER_ORG_ID`): tool call thay mặt org khác bị từ chối; ngữ cảnh discovery chỉ liệt kê được tool. Docker được truy cập qua socket proxy chỉ đọc (`make up-docker-proxy`).
- MCP Registry (`internal/mcp/registry`): discovery qua MCP, ghim hash định nghĩa từng tool; định nghĩa đổi → version mới `pending_review` và tool bị đổi bị khoá tới khi duyệt. Chỉ duyệt được version mới nhất; slug của platform và org chung một không gian tên; tool chỉ thêm được trong transaction tạo version (trigger, migration 00007). Ghi chỉ qua `hqadmin`; API chỉ đọc (`/v1/mcp-servers`). Agent Version tham chiếu được tool đã bật.
- MCP Gateway (`internal/mcp/gateway`, wiring ở `internal/gatewayserver`): `POST /mcp/v1/projects/{project}`, stateless. Pipeline: xác thực (audience riêng `HQ_GATEWAY_OIDC_AUDIENCE`, không tạo user) → rate limit trong bộ nhớ → resolve tool đã bật → validate theo schema đã ghim → policy (ma trận rủi ro ở `policy.go`; client bên ngoài vẫn chỉ đọc) → ngữ cảnh ký → upstream → che secret, cắt kết quả, audit `mcp_tool.call` (không ghi được audit thì không trả kết quả). Tên tool phía client là `<server>.<tool>`.
- Agent Runtime (`internal/agent/runtime`): `Run` là vòng lặp thuần sau interface `Executor` (`ListTools`, `Cancelled`, `CallModel`, `AuthorizeToolCall`, `CallTool`; dữ liệu tuần tự hoá được). Vòng lặp chạy trên Temporal ở process `worker` (xem mục Temporal bên dưới); chỉ khi `HQ_ENV=local` và không có `HQ_TEMPORAL_ADDRESS` nó mới chạy trong process `api` (`LocalRunner`, goroutine nền, không bền vững qua restart). Execution mồ côi quá hạn được đóng `timed_out` khi có người đọc. `mode: single_agent` hoặc `planned` (xem mục Orchestrator bên dưới); `model.policy` là `fixed` hoặc `tiered` (Model Router). Mọi model của task phải có giá hiệu lực tính bằng USD. Chạy version không phải version đang hoạt động cần `agent:publish`. Trần: trên Temporal 8 vòng lặp Agent đồng thời mỗi org (execution đơn Agent chiếm một suất, execution planned chiếm số task song song; đếm trong database dưới advisory lock) và 32 activity mỗi worker; ở chế độ trong process 16 mỗi process, 4 mỗi org; hội thoại mỗi task tối đa 4 MiB. Mỗi bước ghi `execution_steps` theo `(task_id, step_seq)` dưới khoá dòng task; lượt model ghi step + `usage_records` + số cộng dồn trong một transaction (`internal/cost/ledger`). Endpoint: `POST/GET /v1/projects/{id}/executions` (bắt buộc `Idempotency-Key`, trả 202), `GET /v1/executions/{id}`, `/cancel`, `/tasks`, `GET /v1/tasks/{id}`, `/steps` (`include_content` cần `execution:read_content`).
- Tool call của runtime đi qua Gateway bằng execution token (`internal/shared/exectoken`, JWT HS256, `HQ_EXECUTION_TOKEN_KEY` ở `worker`, `gateway` và `api`; bên phát cần thêm `HQ_GATEWAY_INTERNAL_URL`). Gateway có route riêng `/mcp/internal/v1/tasks/{task}` không nhận token OIDC; mỗi request kiểm lại: task còn chạy, khớp execution / project / Agent Version / người khởi tạo, người khởi tạo còn hoạt động (user, membership, org) và còn `mcp_tool:call`, Agent còn `active`, tool nằm trong `tools` của Agent Version (deny thắng trên mọi mục cùng server). Process `api` không nối tới MCP server nào (`internal/mcp/client` chỉ gọi Gateway).
- Temporal (`internal/agent/runtime/durable`, ADR-0002): workflow `AgentExecution` trên task queue `agent-shared`, thân là `runtime.Run`; mỗi bước có I/O là một activity (`runtime.Steps`, dựng bởi `internal/runtimewire`). Lịch sử workflow chỉ chứa tham chiếu và mã lỗi cố định; hội thoại dựng lại từ `execution_steps` ở mỗi lượt model. Activity không tin tham chiếu nhận từ Temporal (đối chiếu task / execution / người khởi tạo với database, tên tool và arguments đọc từ step). Usage được ghi cho mọi lượt provider đã trả lời, kể cả khi step đã bị đóng. `worker` chạy dưới role `app_worker` (migration 00013), từ chối khởi động nếu được cấp khoá của Secrets / LLM / `HQ_SERVICE_SIGNING_KEY` / `HQ_SERVICE_TOKEN_KEY`. Cấu hình: `HQ_TEMPORAL_ADDRESS` (bắt buộc ngoài `local`), `HQ_TEMPORAL_NAMESPACE`, `HQ_TEMPORAL_TLS=1` hoặc `HQ_TEMPORAL_TLS_CERT_FILE` / `_KEY_FILE`, `HQ_TEMPORAL_TLS_CA_FILE` / `_SERVER_NAME` (Temporal tự vận hành với CA nội bộ; CA đó thay kho CA của hệ thống cho riêng kết nối này), `HQ_TEMPORAL_API_KEY`; ngoài `local` kết nối không TLS bị từ chối. Namespace phải có search attribute `OrgId`, `ProjectId` (Keyword). Đổi thứ tự / số lần gọi `Executor` trong `runtime.Run` là đổi workflow: cần versioning và ghi lịch sử mẫu mới (`HQ_UPDATE_REPLAY_FIXTURE=1 go test ./tests/api -run TestDurableExecutions`); `internal/agent/runtime/durable` có test replay không cần Docker.
- Model Router (`internal/ai/router`, ADR-0010): ánh xạ tier → chuỗi model (chính + tối đa 3 dự phòng) nằm ở `settings.model_routing` của organization / project (project ghi đè theo tier), kiểm khi ghi qua hook `tenancy.WithSettingsValidator`; cấu hình hỏng lúc đọc thì dừng (fail-closed). Agent Version `policy: tiered` chạy bằng chuỗi của `default_tier` (mặc định `standard`); model bị tắt, thiếu tool calling, cửa sổ ngữ cảnh quá nhỏ, chưa có giá hoặc thiếu khoá bị loại lúc chọn. Chuỗi chốt lúc tạo task (`agent_tasks.model_chain`, migration 00015 / 00016, bất biến bằng trigger); Gateway chỉ phục vụ model trong chuỗi. Trong một lượt, model kế tiếp được thử khi model trước lỗi tạm thời hoặc không phục vụ được (mã `provider_unavailable` / `model_unavailable` của Gateway); yêu cầu bị từ chối và lỗi của platform không chuyển model; trần 3 vòng × độ dài chuỗi. Step ghi `routing` có cấu trúc (kèm các lần thử lỗi) và `model_id` của model đã trả lời; usage tính theo model đó; Gateway audit cả lượt `llm.call` lỗi.
- Budget (`internal/cost/budget`, cost-management §4): `GET / POST /v1/budgets`, `GET / PATCH / DELETE /v1/budgets/{id}` (`budget:read`, `budget:write`; chỉ USD), phạm vi organization / project / user / agent, chu kỳ `daily` / `monthly` / `total`, `block` hoặc `alert_only`, ngưỡng mềm (audit `budget.soft_threshold`). Budget của execution là `limits.budget` của Agent Version, chụp vào `budget_limit` của execution và task (bất biến bằng trigger, migration 00018). Mỗi lượt gọi model được đặt trước rồi quyết toán ở nơi gọi: Gateway cho model có khoá ở đó (`ModelBudget` trong `llm.go`), bước `CallModel` cho adapter trong process (`runtime.BudgetGate`; ở `worker` chỉ kiểm budget của task). Bộ đếm `Counter`: Redis (Lua, dùng chung `HQ_REDIS_URL` của Gateway) hoặc bộ nhớ ở local; bucket chưa có được nạp từ `usage_records`; không dùng được bộ đếm mà có budget chặn cứng thì từ chối (`budget_unavailable`). Chạm ngưỡng: lượt gọi nhận `budget_exceeded` → `Turn.Blocked` → task / execution kết thúc `budget_exceeded` kèm kết quả dở dang; execution mới nhận 402 khi budget chặn cứng đã chạm ngưỡng theo ledger. Tiền tính bằng số nguyên đơn vị 10^-8.
- Approval và tool ghi (security §4.5): policy thuần ở Gateway (`internal/mcp/gateway/policy.go`): `write` tự do trên non-prod, `destructive` cần một người duyệt, production và `financial` chưa mở, `require_approval: always` của Agent Version làm chặt hơn. Approval (`internal/workflow/approval`, migration 00019 / 00020) gắn với `(task, step_seq, tool, mức rủi ro, hash arguments đã chuẩn hoá)`, hạn 30 phút và không quá hạn task, dùng một lần; Gateway tạo và tiêu thụ nó, `api` nhận quyết định (`GET /v1/approvals`, `GET /v1/approvals/{id}`, `POST /v1/approvals/{id}/decisions`; quyền `approval:read`, `approval:decide`). Người duyệt ≠ người yêu cầu, và với API key thì người yêu cầu là người tạo key (giữ cả ở trigger của bảng). Trong lúc chờ, execution ở `waiting_approval`; vòng lặp chờ qua `Executor.AwaitApproval` (Temporal: signal `approval-resolved` + timer) rồi gọi lại đúng bước đó. Tool không chỉ đọc chỉ chạy trong execution: Gateway giữ chỗ `(task, step_seq)` trong `mcp_tool_claims` trước khi gọi upstream và gửi `idempotency_key`; bước chạy lại nhận `outcome_unknown` → step `unknown` → task `failed` / `tool_outcome_unknown`. Gateway áp lại `max_tool_calls` trên số bước nó đã cho chạy. Bước `CallTool` không ghi nhận một tool có thể đã chạy là "thất bại".
- Orchestrator, `mode: planned` (agent-runtime §5.8): request đưa một kế hoạch DAG (`plan.tasks[]`: `id`, `agent_id`, `goal`, `depends_on`, `on_failure`, `budget`); project phải bật `settings.orchestration.planned_enabled`. `internal/agent/orchestrator` là phần thuần (kiểm kế hoạch: tối đa 16 task, độ sâu 8, song song ≤ 8; bộ lập lịch `Run` sau interface `Engine`; `Aggregate`); việc tạo execution và các bước `BeginPlan` / `BeginTask` / `FinishTask` / `SkipTask` / `FinishPlan` nằm ở `internal/agent/runtime` (`plan.go`, `createPlanned`). Trên Temporal: workflow cha `PlannedExecution` (thân là `orchestrator.Run`) + child workflow `AgentTask` cho từng task (thân là `runtime.Run`); đổi thứ tự gọi `Engine` là đổi workflow. Task phụ thuộc chỉ nhận `output_summary` của task trước trong khối `<task_results>` ở lượt user. `on_failure`: `skip_dependents` (mặc định) / `fail_execution` / `continue`. Mỗi task bắt buộc có budget; tổng không vượt `budget` của execution. Trạng thái execution suy từ các task trong database. Trần theo org đếm theo vòng lặp Agent (execution planned chiếm số task song song). Migration 00021 / 00022. Lịch sử mẫu: `planned_*.json` (ghi lại bằng `HQ_UPDATE_REPLAY_FIXTURE=1 go test ./tests/api -run TestDurablePlannedExecutions`).
- Delegation (agent-runtime §5.9, ADR-0014): Agent Version khai `delegation.can_delegate_to` (≤ 8 Agent cùng project) + `max_depth` (1–5). Model gọi tool nội bộ `delegate_task {agent: <slug>, goal}` (`internal/agent/runtime/delegation.go`; không qua Gateway). Điểm quyết định là hàm database `agent_task_delegate` (migration 00023 / 00024, `SECURITY DEFINER`, tự ghi audit `delegation.create` / `delegation.deny`): idempotent theo (task cha, bước), tuần tự (không giao thêm khi còn task con mở), Agent đích trong `can_delegate_to` và còn `active` đúng version đã chụp, không chu trình, độ sâu ≤ `max_depth` nhỏ nhất của chuỗi tổ tiên, ≤ 16 task mỗi execution, budget con = min(budget Agent đích, phần còn lại của cha trừ một lượt của cha). Ảnh chụp Agent đích ghi lúc tạo execution vào `execution_delegation_sources` / `_targets`. Chạy: `Executor.AwaitTask` → child workflow `AgentTask` (hoặc inline ở local), rồi gọi lại đúng bước; step kind `delegation`. Mức đã tiêu của task gồm cả task con (`agent_task_spent`). Mức sàn ở Gateway: tool `write` do task được giao việc gọi luôn cần duyệt (`delegated_write_requires_approval`). Task kết thúc thì task con còn mở bị đóng theo. Test luật ở `tests/tenant/delegation_test.go`; lịch sử mẫu `delegation_*.json` (`HQ_UPDATE_REPLAY_FIXTURE=1 go test ./tests/api -run TestDurableDelegation`).
- Pause / resume (agent-runtime §5.10): `POST /v1/executions/{id}/pause|resume` (quyền `execution:cancel`; gỡ yêu cầu tạm dừng của NGƯỜI KHÁC cần `execution:resume`). Nguồn sự thật là `agent_executions.pause_requested_at` (migration 00025 / 00026; chỉ `app_api` ghi). Vòng lặp đọc nó cùng yêu cầu huỷ ở ranh giới bước (`Executor.Paused` / `AwaitResume`), task sang `paused` rồi trở lại `running`; trạng thái execution suy từ task (`syncWaiting`: waiting_approval > paused > running). Temporal: signal `execution-resumed` + timer; mốc versioning `control` (`workflow.GetVersion`): execution bắt đầu trước mốc không tạm dừng được. Lịch sử mẫu `*_v0.json` (đường cũ, KHÔNG ghi lại) và `*_v1.json`. Tạm dừng là công cụ vận hành, không phải kiểm soát an toàn (Gateway không thực thi nó; huỷ thì có). Thời gian tạm dừng tính vào hạn.
- Đề xuất kế hoạch bằng LLM (agent-runtime §5.11): `POST /v1/projects/{id}/plan-proposals` chạy Agent lập kế hoạch của project (`settings.orchestration.planner_agent_id`) như một execution `single_agent` trên một yêu cầu do platform dựng (`internal/agent/runtime/planner.go`); `GET /v1/executions/{id}/plan` đọc trả lời và kiểm bằng code (`orchestrator.ParseProposal`; chỉ execution được đánh dấu trong `plan_proposals`, chỉ các Agent đã ghi lúc đề xuất). Agent lập kế hoạch không được có tool / delegation và phải có budget. Chạy đề xuất: người gọi gửi lại qua `mode: planned` (`plan_source = caller`), hoặc `POST /v1/executions/{id}/plan/run` (chỉ người đã đề xuất, trong 24 giờ; platform chạy, `plan_source = model`: goal bọc `<planned_task>`, tool `write` luôn cần duyệt: `model_planned_write_requires_approval`). Migration 00027 / 00028. Worker không có đường nào biến output của model thành task.

## Năm nguyên tắc phân xử

1. **Deterministic trước, LLM sau.** Code hoặc API giải quyết được thì không gọi LLM.
2. **LLM đề xuất, platform quyết định.** Output của model là đầu vào không tin cậy; quyền được thực thi ngoài model.
3. **Một đường duy nhất ra ngoài.** Mọi tool call đi qua MCP Gateway, kể cả `direct_tool`. Worker không giữ credential.
4. **Ghi trước, tối ưu sau.** Usage, audit, execution step ghi ngay từ Phase 1.
5. **Thêm hạ tầng khi có bằng chứng.** Thành phần hạ tầng mới cần ADR. NATS, Vault, OPA, pgvector đang **hoãn có chủ ý**; đừng đề xuất lại nếu chưa chạm điều kiện xem xét lại trong ADR.

## Bất biến không được phá

- Bảng thuộc tenant có `org_id` + RLS `FORCE`; truy vấn chạy trong transaction đã `SET LOCAL app.org_id`. `org_id` lấy từ context, không từ input người dùng.
- Context chỉ gọi nhau qua interface khai báo ở **bên dùng**; không import `store` của context khác; không join SQL xuyên context (trừ báo cáo Cost và Audit).
- Secret không xuất hiện trong prompt, tool arguments, Temporal history, log, trace, phản hồi API. Chỉ `gateway` giải mã được.
- `agent_versions`, `usage_records`, `audit_logs`, dòng `model_pricing` đã hiệu lực: bất biến. Sửa bằng bản ghi mới.
- Không có giá model, tên model hay nhánh code theo tên Agent trong source. Agent tham chiếu tier.
- Mọi vòng lặp và retry có trần theo số lần, thời gian và chi phí.
- Tiền là `NUMERIC(18,8)` / decimal, không float.

## Phạm vi theo phase

Kiểm tra `.docs/roadmap.md` trước khi thêm tính năng. Phạm vi Phase 2 đã có hiện thực trên máy cục bộ (chưa lên staging); **chưa có**: tóm tắt context bằng model, memory theo session. Go · PostgreSQL (`pgx` + `sqlc`, migration bằng `goose`) · Redis · Temporal (từ Phase 2) · OpenTelemetry · `github.com/modelcontextprotocol/go-sdk` · testcontainers · `golangci-lint` với `depguard`.

## Quy ước làm việc

- Tài liệu trong `.docs/` viết bằng tiếng Việt; định danh trong code, tên bảng, tên API bằng tiếng Anh.
- Thay đổi hành vi API → sửa `openapi.yaml` trước. Thay đổi schema → migration + cập nhật `schema.md`. Thay đổi quyết định kiến trúc → ADR mới (`/new-adr`).
- Rule chi tiết theo vùng code nằm ở `.claude/rules/`, tự nạp theo đường dẫn file đang làm. Giao diện web: rule `web-ui.md`, agent `ui-reviewer`, skill `/add-screen` (thêm màn hình) và `/add-ui-dependency` (thêm gói npm).
- Sau một thay đổi đáng kể, chạy `/review-change` để gọi các agent review phù hợp.
